# Isolated native Codex worker

Build explicitly (runtime never pulls and never falls back to host Codex):

```sh
docker build -t gs-codex-worker:0.150.1 docker/codex-worker
```

Docker must use Linux containers. The image installs the official `@openai/codex@0.150.1` native platform package and checks `codex-cli 0.150.1` during build. The factory resolves the local tag to an immutable image ID for both containers. Review and rebuild image changes yourself; no digest download/pull is performed on task execution.

Server configuration:

- `GS_CODEX_MODEL`: default `deepseek-flash`.
- `GS_CODEX_BASE_URL`: default `https://api.deepseek.com`; HTTPS only, port 443, optional API prefix such as `/v1`. The endpoint **must implement the Responses API**. No automatic Chat Completions translation exists. Unsupported model/provider requests fail rather than switching providers.
- `GS_CODEX_UPSTREAM_IP`: optional server-only public IPv4 pin for fake-IP/intercepted DNS environments. Only the gateway receives it. TLS still verifies the configured origin hostname and sends its original SNI; private, loopback, benchmark, link-local and reserved addresses are rejected. Obtain the address through a trusted DNS path, maintain it as DNS TTLs/CDN routing change, and remove it when normal DNS is repaired. No automatic DoH fallback or additional egress domain is enabled.
- `GS_CODEX_API_KEY`: preferred server credential. Otherwise only one unambiguous literal `experimental_bearer_token`, `bearer_token`, or `Authorization = "Bearer ..."` header is extracted server-side from `~/.codex/config.toml`. Personal config is never mounted or copied. No auth.json, environment expansion or arbitrary TOML execution.

## Output transport (EAGAIN fix)

Codex 0.150.1 was reproduced crashing with exit101 while printing a ~75KB UTF-8 JSONL tool event to an inherited Docker stdout pipe: `failed printing to stdout: Resource temporarily unavailable (os error 11)`. The interrupted write leaves an unterminated JSON frame and sometimes half a UTF-8 character. This is not fixed by ignoring invalid JSON, replacing bytes, or Python `set_blocking` (that attempt also failed).

Worker native stdout/stderr now target regular files on the existing bounded 512MiB container-only `/tmp` tmpfs; a raw-byte relay drains in <=64KiB chunks with write-callback backpressure before success exit. Independent100ms checks enforce sampled16MiB stdout/1MiB stderr limits; tmpfs is the hard disk-capacity bound. Stalled output/drain over30seconds fails and tears down the namespace. Files are not mounted back to host and disappear with the container. The adapter permits bounded2MiB JSONL frames to accommodate native ~1MiB command output; redacted tool display is still4000 characters. Overall16MiB stream cap and mandatory terminal success stay enforced.

No-key/no-paid-model fixtures and before/after evidence: `.workspace/verify-codex-protocol/README.md`. A6MB single event passes relay stress testing but is intentionally rejected by the application's2MiB frame policy. The user's original failed raw stream was not retained; these are deterministic reproductions of the same exit101/truncated-JSON/UTF8 symptoms, not a retroactive byte trace of that historical run.

## Boundary

Pass a **disposable staged directory** into `createIsolatedCodexEngine`, not the original project. Always await `dispose()` in `finally` before deleting a stage or publishing results. Task workspace must match that stage. A read-only task gets a read-only stage mount. Other host bind mount is a newly generated, non-secret config directory mounted read-only. No host HOME, Docker socket, SSH agent, host env or personal Codex MCP config enters the worker.

Worker: non-root uid 10001, `--network none`, read-only image, writable bounded `/tmp` tmpfs, dropped capabilities, no-new-privileges, CPU/memory/PID limits. Nested Codex sandbox is set to danger-full-access **inside this Docker boundary** because nested Landlock is not portable across Docker Desktop; host isolation is enforced by Docker mounts and network namespace, not a prompt. Linux host stages must grant uid 10001 suitable access. Windows Docker Desktop bind mounting is supported.

A Docker-managed Unix-socket volume connects the worker to a distinct non-root gateway. This is not a Docker socket. The gateway alone joins a private, per-engine bridge with outbound connectivity. It publishes no TCP ports and mounts no host directories. The worker has no default route or LAN access; localhost HTTP is translated to the socket by an image-owned shim. Gateway permits only JSON `POST /responses`, limits request bodies to 8 MiB, ignores caller authorization and destination headers, injects the real bearer and pins connections to the configured HTTPS origin. DNS answers are restricted to public IPv4 addresses and checked at connection time; literal private IPs, redirects, CONNECT, other paths, upstream auth diagnostics/cookies are denied. It is not a general-purpose proxy. Local fake-IP DNS interception (for example resolving an Internet API to `198.18.0.0/15`) intentionally fails closed with `TRANSPORT_DENIED`; do not whitelist private/benchmark addresses. Configure Docker with a resolver/routing path returning real public addresses.

The credential exists only in server memory and gateway environment/process memory. Docker administrators can inspect it; Docker daemon access is trusted. Worker tools cannot see gateway process environment. Worker tools **can** call the broker with chosen Responses request bodies (so can consume model quota and send staged content to the configured provider). This is necessary model egress, not a data-loss-prevention boundary. Keep budgets, trusted images, server logs and Docker administration secured. Gateway compromise/container escape remains outside this boundary; Docker shares its Linux kernel and is not a VM-grade hostile-kernel sandbox.

Per-run worker containers are force-removed on cancellation and awaited before returning results. `dispose()` removes gateway, all worker names, bridge, socket volume and generated config; it is idempotent and verifies removal. All containers, bridges and socket volumes carry `io.graduatestudio.codex.stage=<SHA256 canonical stage>`; no host path appears in the label. `createIsolatedCodexEngine` rejects existing labeled resources rather than destroying another owner's run. The caller must hold an exclusive cross-process task/stage lease for the full lifecycle (the resource precheck alone is not an atomic lock). After restart, **only after acquiring that lease and establishing the former owner is dead**, await exported `cleanupCodexStage(workspace)` before resuming. It removes and verifies only resources with the exact stage label; never call it against a potentially live task. Worker PID 1 exits after at most 30 minutes and gateway PID 1 after 35 minutes independently of application survival. Docker kills remaining worker namespace processes; the gateway credential-bearing container is no longer live afterward. The gateway also uses `--rm`, removing its environment/inspect metadata on normal daemon-managed exit. Networks, volumes and non-secret temporary config may remain after a crash and need explicit recovery cleanup. No global reaper is installed. Network/daemon failures are surfaced without raw Docker stderr or credentials. No paid model requests are required for image/version, socket allowlist or create/dispose smoke tests.
