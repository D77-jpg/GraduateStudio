# 完整生成重复超时修复

## 确认问题

活动模块第6批多次恢复后恰好8分钟超时，没有写入新代码。旧兼容层把请求预算强制提高至32768，可能增长至65536，还存在SDK与JSON校验层隐藏重试，界面仅显示外层调用次数，缺乏实际模型和请求阶段证据。

## 已实现修复

- 请求使用当前批次指定输出预算，不为所有模型强制保留巨大推理额度。
- SDK自动重试关闭；JSON纠正次数有明确上限，每次请求单独记录与计入预算。
- 根据实际反馈撤销过短120秒截止：单请求默认20分钟，服务端 AI_REQUEST_TIMEOUT_MINUTES 可设5至60分钟；规划/实现总截止为两次请求额度加1分钟（默认41分钟），仍受任务剩余额度/取消信号保护；SDK重试0次，JSON校验最多修正1次，两次请求均使用指定512至20000 token额度，不自动倍增。单请求截止与总任务取消分开，超时以中文说明；不再默默等待8分钟。
- 保存实际服务商/模型、预算、尝试序号、请求状态、耗时与输出字符数；不保存或展示密钥、完整提示词和内部推理内容。
- 在未创建/应用变更集时，超时批次可拆为更小请求；已写入批次或待确认变更不得重排。
- 拆分使用持久化稳定批次身份，不能让新的游标误引用原有批次变更集。
- 旧断点已完成前缀与剩余文件顺序保留；当前历史超时批次在下一次用户继续时先安全拆分，而非再次原样请求。
- 单文件仍超时则保留断点并允许用户直接继续重试，不再要求用户自行拆文件；不无限自动收费重试。
- 本次截止调整相关46个测试、全项目TypeScript与修改文件ESLint通过。尚未触发真实模型重跑，因此延长等待不构成网关连通性或项目完成保证。

## 验证边界

全项目TypeScript与ESLint通过，24个测试文件304个测试通过。覆盖指定额度、SDK无自动重试、JSON有界重试、实际模型快照、无响应传输强制截止、父取消、旧断点拆批、变更集身份隔离与真实请求计数。

测试使用模拟SDK与数据库，不对用户模型发起请求，不自动继续当前任务，不改写现有生成项目代码。请求已开始并不证明网关正在逐字返回；界面如无流式输出只展示真实已记录阶段。
