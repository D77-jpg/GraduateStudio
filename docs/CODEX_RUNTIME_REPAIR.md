# Codex业务运行故障修复闭环

## 问题与本次范围

原链路把“业务任务#9失败，修复”当普通源码修改，只给断网代码副本，没有实际业务错误和运行连接观测。Agent可以持续读管理/测试代码，却无法判断真实服务地址。本次补齐显式业务任务编号的local修复场景，不宣称任意自然语言任务均能自动完成。

新增诊断报告RUNTIME_REPAIR_REPORT：平台按当前项目派生runtime名称、核验资源身份后，在业务后端容器执行固定诊断脚本，读取业务任务及关联模型配置的最小字段，限时一次无载荷TCP探测。只回传任务状态、白名单错误码、服务ID、地址类型和端口、连接结果。无密钥、完整URL、原始错误正文、快照或模型输入输出。

## 编排

- local+明确任务编号和修复意图：模型调用前先采集并记录诊断；每轮及恢复附同样的故障合同，不让模型猜错误。
- 配置、连通性和代码问题分开。无代码diff时重新诊断并暂停，报告“诊断结束／未产生代码变更／需确认”，不再一律报笼统代码失败，不把诊断当修复成功。
- 8分钟无文件字节进展、60次无修改工具操作或5次重复工具操作触发暂停；保留副本、不自动继续收费。不承诺这些界限证明任务不可完成，只是及时停止空转。
- 有代码diff仍进入原人审变更集；应用后独立验证增加运行故障复核。仅观测当前运行版本，不自动重启或把尚未重启的代码说成已生效。
- 非运行中的故障任务提供“运行故障复核（不调用模型）”入口；POST固定诊断route，使用已存储task.message，不接受任意命令/URL。归属校验、full拒绝、运行任务冲突保护；只追加报告，不改变任务结果。

## 安全与限制

Codex Worker仍断网，无Docker socket/宿主HOME/密钥/生产数据库权限；诊断在已有项目runtime内，不给Worker开网。固定端口allowlist，无HTTP、认证、模型生成、业务重试或配置修改。拒绝metadata/linklocal/危险端口，解析后固定数字地址探测；硬超时。端口7863为当前实际模型配置所需显式加入，非允许任意端口。

诊断来源是运行中的项目代码与其依赖，不是独立可信数据库证明；固定脚本import app会执行已有业务源码，输出虽严格枚举/大小限制也不能证明恶意项目无隐蔽信道。仅适用平台独占项目runtime维护边界，不是业务多租户行级授权方案。尚未实现平台只读诊断镜像/独立只读DB凭据，不能对恶意项目保证强信任诊断。

TCP connected只代表socket可连接，不证明TLS、鉴权、模型名、配额或生成正常。收费重试和真实模型配置修改必须另行确认。支持当前Python任务/配置schema；其他栈、歧义任务号、停止runtime或策略阻止均如实报告受阻，不猜测或扫描其他项目。
