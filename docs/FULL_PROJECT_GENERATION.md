# 一次发起的完整项目生成

## 用户入口

项目概览与自主开发页面提供「生成完整项目」。需求功能范围需先保存；默认无需输入分模块指令，也无需选择执行步数。原有自定义指令放在「局部修改 / 高级任务」。

点击会发起一个完整生成任务，可能产生多轮模型调用与费用。平台自动规划依赖有序模块、分批写入代码、准备依赖、执行工程检查并在限额内修复真实失败。

## 内部机制

- 一条父任务统一管理模块、暂停/取消、日志与验收。
- 至少覆盖基础、API、前端、业务、测试、配置、文档；核对已保存需求的功能 ID，拒绝遗漏或虚构范围。
- 每模块内部依然使用完整上下文和每批两个文件的质量约束，不把整套系统塞进一次模型输出。
- 持久化检查点写入 AgentStep，不交给模型编辑工作区文件。
- 完成模块、当前文件计划、批次游标、应用变更、调用/时间预算保存为断点。
- 恢复会跳过已完成模块，并核对中断批次的变更集和文件；发现外部修改冲突时停止保护代码。
- 服务重启后不自动发起收费调用，用户点击「从断点继续」后恢复。
- 已变更需求不按旧计划继续；完成或取消的任务不能恢复。

## 有界自动执行

默认上限：12 个模块、240 个步骤、100 次模型调用、90 分钟累计运行时间、2 轮工程验收修复。恢复不清零预算；预算耗尽明确受阻并保留代码，不假装完成。

工程验收受阻（例如缺工具、数据库服务或受支持测试）不会无限让 AI 修复。构建测试失败可自动进入修复模块，但不能删除测试或降低要求来制造通过。

本轮仍沿用前端 + Maven 的工程验收支持范围；算法效果、真实数据库业务流程、完整端到端和人工交付验收不能由本轮构建检查证明。完整生成任务完成表示模块执行及工程检查完成，不等同于毕业设计自动达到交付标准。

## 数据与运行

无需迁移数据库，保留现有数据、生成项目与此前未提交改动。不主动启动新模型调用，不停止或重启现有运行环境。新入口点击后才执行。

代码尚未自动提交。全项目 TypeScript、ESLint 通过，14 个测试文件、144 个测试全部通过，包含完整模块推进、断点避免重复写入、需求变更/外部修改冲突保护、取消收尾、修复上限与一键 API 兼容性。测试使用模拟模型与执行器，未在用户项目上触发付费生成。

本轮未运行真实模型完整项目生成或浏览器端到端验收，因此不把这些测试当作实际生成质量证明。完整任务不自动提交 git，保留变更集供检查；用户可自行提交。

运行方式仍为单个本地服务进程。进程内项目互斥和数据库事务防止重复发起；本轮未实现多实例分布式执行锁，不应部署多个实例共同调度同一任务。异常退出至恢复之间的时间保守计入预算；若超过预算，恢复会受阻而非重新清零收费调用次数。
