# 取消平台生成硬配额

本次按用户明确要求撤销生成平台人为设置的配额，后续依据实际运行重新制定约束。本文件覆盖此前说明中的预算与截止规则。

## 撤销范围

- 完整/局部生成不按累计运行时间、步骤数、模型调用数停止。
- 不再存在预算追加次数与累计封顶；旧断点中的数字仅用于兼容和历史统计。
- 不人为限定总体模块、模块文件计划、自动工程修复轮数。
- 请求不设平台单次/总体固定超时，用户取消继续有效。
- 不向模型强制传输出token上限；输出能力仍由服务商/模型实际限制决定。
- 完整原文件不按48k/总160k上下文预算拒绝或截断；缺失、二进制或底层读取不完整仍拒绝覆盖。
- 页面只显示实际时间、步骤和请求，不再显示额度分母、预算预警或追加动作。

## 仍保留的正确性保护

权限、项目互斥、安全路径、文件动作覆盖、完整文件、旧断点外部修改冲突及真实构建验收保留。验收失败不得标记完成。重复修复后若相同错误毫无变化，应说明实际阻塞而不是无限重复收费。

动态分批仍是内部执行组织方式，不是项目文件总数限制。依赖安装/语法/构建/测试的子进程超时、输出缓冲和工作区读取完整性限制仍保留为本地工程执行保护；本次取消的是AI开发配额和模型请求截止，不能把这些保护称为已全面移除。用户可主动暂停/取消；取消信号传给模型请求。服务商自身上下文窗口、输出默认值、网关断连、账户余额以及操作系统资源限制不能由本次取消。

## 费用与等待

没有平台累计配额后，运行可能持续较长时间并产生较多费用，需要用户监控。无固定截止的请求可能长时间等待；平台不会声称已发起请求等于模型正在输出。

不自动恢复当前任务、不主动发起模型费用、不修改已生成项目文件。旧检查点可正常恢复，不需要清空历史记录。尚未做真实模型完整生成验证。全项目26个测试文件323个测试通过，TypeScript通过；新增证明超大历史计数/运行时间不会阻止恢复，超过原修复轮次仍继续，旧限额字段不影响操作。服务商默认输出额度可能仍较小；平台不传token上限不等于服务商无限输出。
