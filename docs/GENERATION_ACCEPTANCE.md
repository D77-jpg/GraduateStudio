# 生成与工程验收机制升级

## 目标与边界

不再把单次 AI 输出成功、JS 语法通过或页面能打开等同于可交付毕业设计。本轮修改平台生成与验收机制，不重写现有生成项目，不重置数据库。

## 生成

- 计划最多 24 个文件，按不超过 2 个文件分批实现；每批重新读取已写入的代码并携带完整计划。
- 实现输出必须与本批计划的文件和动作一一对应；拒绝遗漏、重复、计划外路径、不安全路径、空实现和明显全文件占位。
- 修改已有文件必须提供完整原文件上下文，超过预算或读取结果截断时拒绝覆盖，不再依据前半段内容重写文件。
- 自动优先读取清单、入口、接口、数据库模型；提示词要求后端接口、真实持久化、构建配置和可运行测试，不接受以纯内存演示代替业务实现。
- 执行步骤上限真正生效；预估预算不足时在代码生成前失败，避免悄悄漏做。
- 任务取消信号传递给模型调用；写入变更前检查暂停/取消。
- 每一步保存实际输出，失败保留已应用变更和错误信息，不自动删除用户项目。

提示词和静态检查不是功能正确性的证明；它们是第一层约束。

## 工程验收

支持范围为具有 client/package.json（或根 package.json）的前端与 server/pom.xml 的 Maven 后端。其他后端栈目前明确标记验收受阻，不能自动宣布通过。

- 前端声明的构建脚本必须属于受支持真实构建命令，再执行 npm 构建。
- 前端须具备受支持的直接 Vitest 测试脚本，执行测试而不是仅验证存在字符串。
- 后端执行 Maven verify，并要求真实测试证据；没有工具、测试或配置时标记受阻。
- 扫描明确的“本地演示数据”“后续接入后端”等占位声明；命中阻止验收通过，未命中不代表功能完整。
- 命令固定、输出与运行时间有界，取消/超时不计为通过。构建与测试会执行生成项目自身代码，不是安全沙箱。
- 报告保存在任务步骤中，无数据库迁移。只允许工程验收通过后标记本次任务完成并进入自动提交。
- 构建/测试失败不会自动让 AI 反复修改测试来掩盖错误；目前返回真实报告，由用户按模块继续修复。

## 状态解释

- 工程检查通过：本轮受支持的构建和测试检查通过；不代表整个毕业设计可交付。
- 验收未通过：有真实失败结果。
- 验收受阻：缺少工具、受支持栈、测试或完整证据。
- 历史任务：未执行新版工程验收，原完成状态不能作为交付证明。

还需要数据库初始化/连接、真实业务接口、端到端用户流程、权限/持久化、算法评测、视觉人工审查、文档与部署验收。平台不伪造这些结果，也不改历史项目的已有进度数字。

## 生效与已有项目

新机制用于升级后新启动的任务，不追溯重跑历史任务，不自动发起收费模型请求，不中断运行环境。本轮未主动重启开发服务，也未对用户生成项目执行新构建。开发环境按框架热更新加载服务端变更；已在内存运行的旧任务不是新版验收证明。

本轮同时保留此前新增的开发过程面板与修复消息长度修正。代码尚未自动提交。

## 平台验证结果

- 全项目 TypeScript 与 ESLint 通过。
- 11 个测试文件、122 个测试通过；新增覆盖生成覆盖率、完整文件上下文、取消信号、验收规划与真实测试摘要判定。
- 修复审查发现的步骤预算边界、提交期间取消状态、结构化报告被截断，以及 Maven/Vitest 忽略失败但返回零退出码的误判。
- 验收测试使用隔离临时目录和注入的执行结果，不调用线上模型、不构建用户正在运行的项目。
- 本轮未做 Next 生产构建或重启运行中的开发服务；也未完成真实业务端到端交付验收。
